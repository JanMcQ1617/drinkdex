## 0. Motion policy for this round (item b, decided)

Jan: "there are no smooth transitions on the app". The old rule ("tab
changes are a cut", `(tabs)/_layout.tsx:46-56`, FloatingTabBar.tsx:47-55)
came from build 15's JS slide that stalled halfway. It is replaced by:

**Motion is wanted, but only motion that UIKit or the native driver runs,
that the finger can interrupt, and that rests fully drawn.**

| Moment | How it moves | Reduce Motion |
|---|---|---|
| Changing tab by swipe | react-native-pager-view (UIKit collection view paging), moved by the finger | unchanged: it is the finger |
| Changing tab by tapping the bar | pager `setPage` (native animated scroll) | `animationEnabled: false`: `setPageWithoutAnimation`, a cut |
| Tab bar's "where you are" rule | one indicator, `translateX` interpolated natively from the pager's `position` (Animated, native driver, no clock) | still follows the finger; a tap jumps it |
| Opening Post a drink (+) | native `fullScreenModal`, iOS cover-vertical rise from the bottom; close slides it down | `animation: 'fade'` |
| Likers list | RN `Modal` `presentationStyle="pageSheet"` (UIKit slide) | UIKit's own handling |
| Photos arriving | expo-image `transition` (native crossfade), as today | as today |
| Press feedback | unchanged: fills; PressableScale on media tiles (rests at scale 1) | as today |

**No Reanimated layout animations, still.** Rule 3 of
`scripts/check-design.mjs` (no `entering`/`exiting`/`*Transition`/`Layout`)
stays exactly as it is. specs/06 §1 and §3.8 proved that Reanimated 4.5.x's
frame loop stalls for 10-20 s after a cold start in iOS Release builds
(software-mansion/react-native-reanimated#10094, no fix, SDK 57 pins 4.5.x)
and that exits can leave ghost views (#10275). A `LinearTransition` that
stalls leaves a row drawn at its old frame over its neighbours, which is not
"resting fully visible". List inserts and removals (My Bar ticks, a row
added to One ingredient away, the Log window's find/compose swap) therefore
change in the same commit, with no animation, and say so in a comment. RN's
`LayoutAnimation` is not used either (Fabric's implementation runs delete
animations on opacity). Rule 15 (no timed RN `Animated`) stays.

### Change

Replace `Tabs` with expo-router's vendored material top tabs:

```tsx
import { TopTabs } from 'expo-router/js-top-tabs';
```

`TopTabs` = `withLayoutContext(createMaterialTopTabNavigator().Navigator)`
(node_modules/expo-router/build/layouts/TopTabsClient.js). Its view
(build/react-navigation/material-top-tabs/views/MaterialTopTabView.js) passes
every prop it does not know straight to react-native-tab-view's `TabView`,
which on iOS uses `PagerViewAdapter` (react-native-pager-view). Props to set:

```tsx
<ScrollChromeProvider>
  <TopTabs
    tabBarPosition="bottom"            // TabView renders the bar AFTER the pager, so it draws on top
    tabBar={(props) => <FloatingTabBar {...props} />}
    initialLayout={{ width: Dimensions.get('window').width }} // pages side by side from the first frame
    style={{ backgroundColor: colors.bg }}
    screenOptions={{
      lazy: true,
      lazyPreloadDistance: 0,
      swipeEnabled: true,
      animationEnabled: !reducedMotion, // useReducedMotion() from react-native-reanimated
      sceneStyle: { backgroundColor: colors.bg },
    }}>
    <TopTabs.Screen name="index" options={{ title: 'Home', tabBarAccessibilityLabel: 'Home', tabBarIcon: tabIcon('home'), lazyPlaceholder: () => <TabPlaceholder title="Home" ground="lining" /> }} />
    <TopTabs.Protected guard={REELS_ENABLED}>
      <TopTabs.Screen name="reels" options={{ …as today…, sceneStyle: { backgroundColor: colors.reelGround }, lazyPlaceholder: () => <TabPlaceholder title={COPY.label} ground="reel" /> }} />
    </TopTabs.Protected>
    <TopTabs.Screen name="dex"  … lazyPlaceholder: () => <TabPlaceholder title="Dex" /> />
    <TopTabs.Screen name="bar"  … lazyPlaceholder: () => <TabPlaceholder title="My Bar" /> />
    <TopTabs.Screen name="profile" … lazyPlaceholder: () => <TabPlaceholder title="Profile" /> />
  </TopTabs>
</ScrollChromeProvider>
```

Facts the builder can rely on (read from the vendored source):

- **Hiding Reels.** `withLayoutContext` (build/layouts/withLayoutContext.js:49-55)
  flattens `<TopTabs.Protected guard={false}>` children into
  `protectedScreens`, so `reels` is not in the navigator's state at all:
  no page, no swipe, no slot. `(tabs)/reels.tsx` keeps its
  `<Redirect href="/" />` for a typed path. `record.tsx:71`
  (`dismissTo('/reels')`) only runs while Reels is on.
- **Events.** The router is `TabRouter`, so `navigation.getState().type`
  is still `'tab'`. `navigation.addListener('state')` in
  `(tabs)/bar.tsx:146` and `SignInScreen.tsx:196-209` (useOtherTabInFront)
  work unchanged. `useScrollToTop` (Home, Dex, My Bar, Profile, Reels)
  listens for `tabPress` on the nearest `'tab'` navigator: FloatingTabBar
  keeps emitting `tabPress` exactly as now, so tap-to-top keeps working.
  `useIsFocused` / `useFocusEffect` fire on index change. New events
  `swipeStart` / `swipeEnd` exist; nothing needs them.
- **Laziness.** `lazy: true` + `lazyPreloadDistance: 0`: a tab mounts the
  first time it is focused or a drag toward it starts (SceneView's enter
  listener), and then stays mounted (as bottom tabs did). Distance 1 would
  mount the Dex grid at launch beside Home, which is the cost the lag fix
  (build 13) fought; 0 keeps launch exactly as today. A tab tapped from
  three slots away animates past the middle pages, which show their
  placeholder; that is why the placeholder must be cheap and not blank.
- **Keyboard.** TabView's default `keyboardDismissMode="auto"` dismisses
  the keyboard on a page change and on drag. Keep it.
- **tabBarIcon.** Material top tabs type it `(props: { focused; color }) =>
  ReactElement` with no `size`: make `size` optional in `tabIcon()` (the
  bar always passes it). `tabBarBadge` is typed `() => ReactElement` there:
  widen FloatingTabBarProps' `tabBarBadge` to accept either (nothing sets
  it).
- **pager-view 8 on iOS** is a SwiftUI `TabView(.page)` over a
  UICollectionView (node_modules/react-native-pager-view/ios/PagerView.swift).
  It rebuilds itself when its child count changes (`.id(children.count)`),
  so the set of tabs must stay constant while the app runs (it does:
  REELS_ENABLED is a build-time flag). Its `overdrag` defaults to false, so
  Home and Profile do not rubber-band past the ends.

**FloatingTabBar** (`src/components/FloatingTabBar.tsx`):

1. Accept the extra props TabView hands the bar: `position:
   Animated.AnimatedInterpolation<number>` (and ignore `layout`, `jumpTo`).
   Keep the structural props type; `position` optional so the file still
   type-checks standalone.
2. Keep `onPress` as is (emit `tabPress`, then `navigation.navigate`), plus
   `haptic.select()` only when the index actually changes (also after a
   swipe? No: a swipe is its own feedback; tick on taps only, as today).
3. Replace the per-slot static indicator with ONE indicator on the bar's
   top edge, `translateX = position.interpolate({ inputRange: routeIndices,
   outputRange: slotLeftFor(routeIndex) })`. Slots: `n = visible.length +
   1` equal slots (the + is one), slot width `(barW - 2*stroke.edge -
   2*BAR_PAD) / n`, route i sits in slot `i < fabAt ? i : i + 1`. `barW`
   from the bar's onLayout (it already measures height). Wrap it in the
   same `motion.slot` translateY so it rides the slab's top edge as the bar
   compacts. Until `barW` is known, or with no `position`, fall back to the
   current per-slot indicator, so a missed layout never loses it.
4. Glyph fill and label weight still switch on `state.index` (after the
   swipe settles). That is the non-motion cue, as now.
5. Update the header comment: "ONE MOTION, MOVED BY THE FINGER" now covers

**ScrollChrome** (`src/components/ScrollChrome.tsx`): no behaviour change.
`useTabBarCollapse(focusedRoute.name)` still rebuilds on index change, so a
tab arrives with the full bar. Update comments that say tab changes are a

**TabPlaceholder** (NEW `src/components/TabPlaceholder.tsx`): what a page
shows until it mounts. Static (no timer, no spinner, no animation), cheap,
never blank: the page's ground with its own Grain, and the top bar's title
where the real bar will be (safe-area inset + `layout.topBar`, title in
`textRole.barTitleLg`, centred, `maxFontSizeMultiplier={1.3}`). Grounds:
`'paper'` (default: Dex, My Bar, Profile), `'lining'` (Home: lining with the
wordmark in `textRole.wordmark`, `colors.onLining`), `'reel'`

(`useIsFocused`, `useNavigation`): `renderLazyPlaceholder` runs outside the

`accessibilityLabel` on the root: "`<title>`, loading".

### Edge cases

### Migration (NEW `supabase/migrations/021_post_likers.sql`)

SECURITY **INVOKER**, decided: the four read policies (posts_read,
likes_read, profiles_read, follows_read) already say exactly what the
caller may see, blocks both ways included; a definer function would bypass
them and have to re-implement each rule (017's `recent_pours` is the

Draft (the builder reads it against schema.sql's real names, like 020's

ADDS / ORDER / VERIFY AFTERWARDS):

```sql

do $$
begin
  if to_regclass('public.schema_migrations') is null then
    raise exception '021 needs 009 (public.schema_migrations). Apply the earlier migrations first.';
  end if;
  if to_regprocedure('private.my_block_set()') is null then
    raise exception '021 needs 011 (private.my_block_set). Apply the earlier migrations first.';
  end if;
end $$;

-- 1. A post's likes, newest first (the likers list and the summary's tie-break).
create index if not exists likes_post_recent_idx on public.likes (post_id, created_at desc, user_id desc);

-- 2. One liker to name per post: someone you follow if any liked it, else the newest.
--    Never you, never anyone blocked either way, nothing for a post you cannot see.
--    Posts with no such liker return no row. At most 100 posts per call.
create or replace function public.post_like_summaries(p_post_ids uuid[])
returns table (post_id uuid, user_id uuid, username text, display_name text,
               accent text, avatar_path text)
language sql
stable
security invoker
set search_path = ''
as $$
  with me as (
    select (select auth.uid()) as id, (select private.my_block_set()) as blocked
  ),
  wanted as (
    select distinct w.id from unnest(p_post_ids[1:100]) as w(id)
  )
  select p.id, f.user_id, f.username, f.display_name, f.accent, f.avatar_path
  from me
  cross join wanted w
  join public.posts p on p.id = w.id
  cross join lateral (
    select pr.id as user_id, pr.username, pr.display_name, pr.accent, pr.avatar_path
    from public.likes l
    join public.profiles pr on pr.id = l.user_id
    where l.post_id = p.id
      and l.user_id <> me.id
      and not (l.user_id = any (me.blocked))
    order by exists (select 1 from public.follows fo
                     where fo.follower_id = me.id and fo.following_id = l.user_id) desc,
             l.created_at desc, l.user_id desc
    limit 1
  ) f
  where me.id is not null
    and not (p.author_id = any (me.blocked));
$$;

-- 3. Everyone who liked one post, newest first, a page at a time (keyset on
--    created_at, user_id), with whether you follow each. You are included.
create or replace function public.post_likers(
  p_post_id uuid,
  p_limit integer default 50,
  p_before_at timestamptz default null,
  p_before_user uuid default null)
returns table (user_id uuid, username text, display_name text, accent text,
               avatar_path text, liked_at timestamptz, followed_by_me boolean)
language sql
stable
security invoker
set search_path = ''
as $$
  with me as (
    select (select auth.uid()) as id, (select private.my_block_set()) as blocked
  )
  select pr.id, pr.username, pr.display_name, pr.accent, pr.avatar_path, l.created_at,
         exists (select 1 from public.follows fo
                 where fo.follower_id = me.id and fo.following_id = pr.id)
  from me
  join public.posts p on p.id = p_post_id
  join public.likes l on l.post_id = p.id
  join public.profiles pr on pr.id = l.user_id
  where me.id is not null
    and not (p.author_id = any (me.blocked))
    and not (l.user_id = any (me.blocked))
    and (p_before_at is null
         or (l.created_at, l.user_id)
            < (p_before_at, coalesce(p_before_user, 'ffffffff-ffff-ffff-ffff-ffffffffffff'::uuid)))
  order by l.created_at desc, l.user_id desc
  limit least(greatest(coalesce(p_limit, 50), 1), 100);
$$;

revoke all on function public.post_like_summaries(uuid[])                          from public, anon;
revoke all on function public.post_likers(uuid, integer, timestamptz, uuid)        from public, anon;
grant execute on function public.post_like_summaries(uuid[])                       to authenticated;
grant execute on function public.post_likers(uuid, integer, timestamptz, uuid)     to authenticated;

insert into public.schema_migrations (version)
values ('021_post_likers') on conflict (version) do nothing;
```
