### 0.1 Three findings that change what was asked, and what this spec does about each

1. **Story music as asked is very likely an App Review rejection.** Apple's App Review Guidelines, 5.2.5, say iTunes and Apple Music previews "may not be used for their entertainment value", and give background music to a photo collage as the example; 4.5.2(ii) says that playing a specific song at a particular moment needs the rights-holders' permission (sync rights), MusicKit or not. A preview that starts by itself under a friend's photo is that example. So the feature is built (behind its flag, default off) with **two** modes, and the spec recommends the second:
   - `autoplay`: Jan's original. The preview plays while the story is shown, with a mute control. Do not ship it without written permission from Apple or the rights-holders.
   - `tap` (recommended): the story carries a **song tag** (artwork, title, artist, "Listen on Apple Music"); the preview plays only when the viewer taps the tag's play button, as a preview *of that song*, with the link to it. That is the use previews exist for. It is still Jan's call (§20), and still needs the official badge (§13.3).
   - Both modes keep what 5.2.5 requires of any app that offers previews ("you must display a link to the corresponding music in iTunes or Apple Music"): the credit is always on screen beside a playable preview, in the viewer and in the picker. 4.5.2(ii) says cover art and metadata may only be used in connection with music playback: the artwork appears only on the song tag and the picker rows, never in a share image, a thumbnail or marketing. No new native module: previews play through expo-video, already in the binary for Reels and the intro (§2.9).
2. **Wine on the lining is invisible** (1.22:1, v3 §4.1), and Home's stories sit on the lining. "Unseen = wine ring" is drawn in **lit wine**, `storyRing` `#BC6B75`: 4.37:1 on the lining, 3.71:1 on its worst grain pixel, so it clears the 3:1 a UI cue needs and still reads as the brand's wine. Seen is a thin muted ring (§4.2).
3. **A post is one row per drink** (`posts_one_per_drink`, migration 007): posting a drink again adds a photo to the old post. That decides three things: (a) a song belongs to the **photo row** (`post_photos`), not the post, so a re-post with no song does not inherit last month's (§13.1 §1); (b) a tournament counts a drink when its post is created **or a photo is added to it** inside the window, which is what "posted during the tournament" means here (§11.2); (c) "Delete" on your own story deletes the whole post for that drink, every photo of it, as Delete post does, and the confirmation says so in the same words (§5.1).

### 0.2 One addition Jan did not ask for, kept because of App Review 1.4.3

Tournaments count **at most 3 new drinks per member per day** (the tournament's calendar day). Guideline 1.4.3 forbids apps that encourage excessive drinking; a contest to try the most drinks in a week is the shape a reviewer reads that way, and "10 new drinks tonight" is exactly what an uncapped count rewards. The cap is one server constant (`private.tournament_daily_cap()`, §13.1), shown in the rules line on every tournament screen. Jan confirms or changes the number (§20).

### 1.2 Engineering constraints

1. **No layout entrance animations.** check-design rule 3 unchanged.
2. **Every motion rests in the fully visible state, and none of the new motion runs on Reanimated's frame loop.** The new chrome motion (tab bar compaction, Home bar hide) is scroll-linked through React Native's own `Animated` with `useNativeDriver: true` (an `Animated.event` on the list's `onScroll`, `diffClamp`, `interpolate`): it is moved by scroll events on the native side, not by a timer, so the Reanimated stall of specs/06 cause 1 (issue #10094) cannot touch it, and at scroll offset 0 every value is the identity. The tab transition is the navigator's own native-driven `Animated.timing`, **translate only** (§3.2). New rule 15 (§16.1) forbids any other `Animated.timing/spring/decay` from react-native in `src/`.
3. **Images in small frames use `enforceEarlyResizing`** (story circles, song artwork, tournament avatars go through `Avatar`). check-design rule 9.
4. **WCAG AA**: every new pair is in §16.2 and asserted by `scripts/check-contrast.mjs`. **Dynamic Type**: new text caps at 1.3 where it sits in a fixed frame (story labels, tab bar, song tag), body text uncapped. **VoiceOver**: labels in each section; the Home bar never hides and the tab bar never compacts while VoiceOver is running (§3.3).
5. **Generated data** (`src/data/drinks.json`, `src/data/drinkPhotos.ts`) is produced by scripts. The `rarity` field stays in drinks.json, untouched, and the generators keep validating it; **nothing in `src/` reads it** after §7 (check-design rule 14).
6. **Never install anything.** Typed routes: a package that adds or moves a route regenerates `.expo/types/router.d.ts` before `tsc` by starting Metro once on a port no other worktree uses (`CI=1 npx expo start --port 81NN`, where NN is unique to the package) and stopping it once the types file is rewritten; never on 8081, never with another project's Metro running (the shared-cache trap). A package that only *links* to a route another package creates uses the `as Href` helpers in `src/lib/tournaments.ts` (§13.4), so it compiles before that route exists.
7. **What a build agent can and cannot check.** This project has no dev client (`expo-dev-client` is not installed), simulator builds are off the table on Jan's machine, and the phone is Jan's. So no agent runs the app. An agent proves its package with the gate (§19.1.7), by reading the code paths it changed, and, for drawings that are plain SVG (the new glyphs), with a headless-Chrome render. Every check that needs the running app is in §21, for Jan's Release-build pass (§20.9). A "done when" in §19 never asks an agent to look at a running app.

### 3.2 The tab transition: a 24pt nudge, translate only

Remove `animation: 'none'`. Add to `screenOptions`:

```tsx
/*
 * A 24pt slide, 180ms, translate ONLY. Opacity is what blanked tabs
 * (specs/06 cause 2: a native progress value that came to rest away from 0
 * left a page at partial opacity). Here a progress value that stalls
 * anywhere leaves the page fully drawn, at most 24pt to one side.
 *
 * `animation` must stay unset: BottomTabView's hasAnimation() reads
 * `animation` first and only falls back to `transitionSpec` when it is
 * undefined, so animation: 'none' would switch this off.
 */
transitionSpec: reduceMotion
  ? { animation: 'timing', config: { duration: 0 } }
  : { animation: 'timing', config: { duration: 180, easing: Easing.out(Easing.cubic) } },
sceneStyleInterpolator: ({ current }) => ({
  sceneStyle: {
    transform: [
      {
        translateX: current.progress.interpolate({
          inputRange: [-1, 0, 1],
          outputRange: [-TAB_NUDGE, 0, TAB_NUDGE],
        }),
      },
    ],
  },
}),
```

- `TAB_NUDGE = 24`, a local constant in `(tabs)/_layout.tsx`. `Easing` from `react-native`. `reduceMotion` from Reanimated's `useReducedMotion()` (a settings read, not a worklet), already used across the app.
- Inline, so TypeScript infers the interpolator's parameter type (the vendored `BottomTabSceneInterpolationProps` has no public subpath).
- What it does: the incoming page slides 24pt in from the side of the tab it came from while the outgoing one slides 24pt the other way, under it (the focused scene has zIndex 0, the others −1, and every scene has an opaque `sceneStyle`). Reels keeps `sceneStyle: { backgroundColor: colors.reelGround }`.
- Known consequence, accepted: with any animation configured, BottomTabView keeps screens to the *left* of the focused tab attached at activity state 1 (its interpolation extends its flat first segment, specs/06 §2). ### 3.3 The tab bar compacts on scroll down

`src/components/FloatingTabBar.tsx`. Full (rest): today's bar. Compact: a 48pt glyph-only bar. Driven by `c ∈ [0, 1]` from `useTabBarCollapse(focusedRouteName)` (§3.4): 0 at rest, at the top of a list, after any upward scroll of 48pt, and on arriving at a tab; 1 after 48pt of downward scroll.

Implementation, transforms and opacity only, all `Animated` from `react-native` (native driver):

- The slab (fill, 1pt edge, radius 12, `elevation.barDark`) becomes its own absolute-fill `Animated.View` behind the row, with `transformOrigin: 'bottom'` and `transform: [{ scaleY: interpolate(c, [0, 1], [1, (barH − labelBlock) / barH]) }]`. `barH` is the bar's laid-out height (onLayout, stored when it changes; initial `layout.tabBar`); `labelBlock = 3 + typeScale.tag.lineHeight × min(fontScale, 1.3)` (17 at the default size). At compaction the 1pt edge draws at ≈0.73pt top and bottom and the corners at 12×8.8: accepted, below what reads at arm's length.
- Each tab slot's content (glyph box + label) gets `translateY: labelBlock × c`, which centres the glyph in the compacted slab. Labels get `opacity: interpolate(c, [0, 0.6], [1, 0], clamp)`, so they are gone before they reach the slab's foot. The 2pt indicator rides the slab's top edge: `translateY: labelBlock × c`.
- The + (centred on the full row) gets `translateY: (labelBlock / 2) × c`.
- `TAB_BAR_CLEARANCE` stays 84: the rest state is the full bar, and content padding must clear it.
- Hit areas move with the transforms (Fabric hit-tests transformed views); each slot stays ≥ 44 × 44.
- **VoiceOver running**: `c` is the constant 0 (no compaction). The provider listens to `AccessibilityInfo` `screenReaderChanged`.
- A stall cannot happen on this path (§1.2.2); if the native driver ever left `c` at an intermediate value, the bar is still a working bar with every glyph visible.

### 3.4 `src/components/ScrollChrome.tsx` (new): one scroll source per tab

```ts
export type ChromeTab = 'index' | 'dex' | 'bar' | 'profile';
export const CHROME = { collapse: 48 } as const;

/** In (tabs)/_layout.tsx, around <Tabs>, so both the tab bar and every tab screen are inside it. */
export function ScrollChromeProvider(props: { children: React.ReactNode }): JSX.Element;

/**
 * For a tab's main list. Pass `onScroll` to an Animated.FlatList / Animated.SectionList /
 * Animated.ScrollView from react-native, with scrollEventThrottle={16}.
 * onScroll = Animated.event([{ nativeEvent: { contentOffset: { y: scrollY } } }],
 *   { useNativeDriver: true, listener }) where the listener records the last y (JS) and
 * calls the screen's own `listener` (e.g. useScrolledPast's handler), read through a ref so
 * the event object is created once per tab and never rebuilt.
 */
export function useTabScroll(
  tab: ChromeTab,
  listener?: (e: NativeSyntheticEvent<NativeScrollEvent>) => void,
): { onScroll: (...args: unknown[]) => void; scrollY: Animated.Value };

/** FloatingTabBar only: 0..1. Rebuilt whenever the focused tab changes, from
 *  diffClamp(clampTop(scrollY) − lastY at that moment, 0, CHROME.collapse), so arriving at a
 *  tab always shows the full bar (a native diffclamp node takes its first input unclamped:
 *  subtracting the current y makes that input 0). Constant 0 for a non-chrome tab (reels)
 *  and while VoiceOver runs. */
export function useTabBarCollapse(focusedRouteName: string | undefined): Animated.AnimatedInterpolation<number>;

/** Home's bar (§4.1): 0..distance, 0 = shown. Rebuilt, like useTabBarCollapse, each time
 *  `tab` regains focus: diffClamp(clampTop(scrollY) − lastY at that moment, 0, distance), so
 *  coming back to Home always shows its bar (otherwise a bar hidden when you left would still
 *  be hidden over a scrolled feed). Constant 0 while VoiceOver runs. */
export function useHideOnScroll(tab: ChromeTab, distance: number): Animated.AnimatedInterpolation<number>;
```

`clampTop(y) = y.interpolate({ inputRange: [0, 1], outputRange: [0, 1], extrapolateLeft: 'clamp', extrapolateRight: 'extend' })`: a rubber-band pull past the top never counts as an upward scroll. A bounce at the foot of a list reveals the bar, as it does in Instagram; accepted.

Who wires it (stage 2 unless noted): Home `useTabScroll('index')` (H), Dex `'dex'` (X), My Bar `'bar'` (N, §3.5), own Profile `'profile'` (R, through a new optional `chromeTab` prop on `ProfileView`, so the pushed `user/[id]` profile does not register). Each list moves from the RN component to its `Animated.*` twin; `useScrollToTop` keeps working (the Animated wrapper forwards its ref).

## 11. Tournaments (item 6)

### 11.1 What a tournament is

Friends compete over a few days to try the **most different drinks**. Each different drink a member posts during the tournament counts **once**; posting the same drink again adds nothing; how much anyone drinks is never counted, shown or mentioned. Anyone can host.

| Rule | Value | Where enforced |
|---|---|---|
| Name | 1 to 40 characters, one line, through the content filter | migration 020 (check + trigger), client pre-check |
| Starts | now (within 5 minutes) up to 30 days ahead | `create_tournament` |
| Length | 1 to 31 days | table check |
| Goal | none ("most by the end"), or first to N different drinks, N 2 to 100, and N no more than 3 × the tournament's length in days (a goal the daily cap makes unreachable is refused: "First to 10" in 3 days could only be won by nobody) | table check; `create_tournament` (`invalid_goal`); the client greys out such goal chips |
| Who can be invited | people the host follows, not blocked either way, by the host only | `add_invitees` |
| Size | at most 50 members, host included | `add_invitees` |
| Hosting | at most 5 unfinished tournaments at once, at most 10 created per 30 days | `create_tournament` |
| Invitations | accept or decline; once declined (or left) a person cannot be invited to that tournament again | `respond_to_tournament`, `add_invitees` |
| Joining late | an accepted member's drinks count from the tournament's start, not from when they joined | `tournament_standings` |
| Daily cap | at most **3** new drinks per member count per calendar day, in the host's time zone. A drink first posted after that day's 3 never counts in that tournament, even if it is posted again on a later day, so the cap never gives anyone a reason to have a drink twice | `private.tournament_daily_cap()`, `tournament_standings` |
| Ends | at its end date, when the host ends it, or the moment someone reaches the goal | `tournament_finish_at` |
| Winner | goal set and reached: the first to reach it. No goal, or a goal nobody reached by the end: the most different drinks; a tie goes to whoever got there first. Nobody posted: no winner | `tournament_standings` order |
| Dates | a start of Now, Tomorrow or Next Monday and a length of 3 days, 1 week, 2 weeks or 30 days. Chips, not a calendar: there is no date-picker module in the binary and none may be added (§1.2.6); every choice is a valid window by construction | client; `create_tournament` re-checks |
| Results | frozen the first time anyone opens a finished tournament; deleting a post afterwards changes nothing | `finalize_tournament` |
| Visibility | the host and invited or accepted members only; anyone blocked either way is left out of every list, and a block between the host and a member removes that member | RLS, `tournament_board`, block trigger |
| Prizes | none, ever. No entry fee, nothing of value (so App Review 5.3's contest rules do not apply; the in-app rules still say Apple is not a sponsor) | copy |

### 11.2 What counts as "posted during the tournament"

For each accepted member and each **catalogue** drink (`drink_id !~ '^u_'`; drinks people add cannot be posted anyway), the drink's first *event* inside the window, where an event is that member's post for the drink being created, or a photo being added to it (`post_photos.created_at`; one post per drink, §0.1). The drink counts at that moment, unless that member already has 3 counted drinks that day. Deleting the post before the tournament ends removes it from the count.

returns trigger language plpgsql security definer set search_path = '' as $$
begin

-- Every accepted member's standing, counting events before `upto`. Not
-- block-filtered: callers filter what they show. Order = rank.
create or replace function private.tournament_standings(t uuid, upto timestamptz)
returns table (user_id uuid, distinct_drinks integer, today_counted integer,
               reached_at timestamptz, target_at timestamptz, rank integer)
language sql stable security definer set search_path = '' as $$
  with tt as (select starts_at, tz, target from public.tournaments where id = t),
  members as (select m.user_id from public.tournament_members m
              where m.tournament_id = t and m.status = 'accepted'),
  events as (
    select p.author_id, p.drink_id, p.created_at as at
    from public.posts p join members m on m.user_id = p.author_id cross join tt
    where p.created_at >= tt.starts_at and p.created_at < upto and p.drink_id !~ '^u_'
    union all
    select p.author_id, p.drink_id, ph.created_at
    from public.post_photos ph join public.posts p on p.id = ph.post_id
    join members m on m.user_id = p.author_id cross join tt
    where ph.created_at >= tt.starts_at and ph.created_at < upto and p.drink_id !~ '^u_'
  ),
  firsts as (select author_id, drink_id, min(at) as first_at from events group by author_id, drink_id),
  dayed as (
    select f.author_id, f.drink_id, f.first_at, (f.first_at at time zone tt.tz)::date as day,
           row_number() over (partition by f.author_id, (f.first_at at time zone tt.tz)::date
                              order by f.first_at, f.drink_id) as nth_that_day
    from firsts f cross join tt
  ),
  counted as (
    select author_id, first_at, day, row_number() over (partition by author_id order by first_at) as nth
    from dayed where nth_that_day <= private.tournament_daily_cap()
  ),
  per as (
    select m.user_id,
           count(c.first_at)::integer as distinct_drinks,
           (count(c.first_at) filter (where c.day = (now() at time zone tt.tz)::date))::integer as today_counted,
           max(c.first_at) as reached_at,
           min(c.first_at) filter (where tt.target is not null and c.nth = tt.target) as target_at
    from members m cross join tt left join counted c on c.author_id = m.user_id
    group by m.user_id, tt.tz, tt.target
  )
  select user_id, distinct_drinks, today_counted, reached_at, target_at,
         (row_number() over (order by target_at asc nulls last, distinct_drinks desc,
                                      reached_at asc nulls last, user_id))::integer
  from per;
$$;

-- When counting stops, or null while it is still running. A goal reached
-- stops it at that post (the winning post counts: + 1 microsecond).
create or replace function private.tournament_finish_at(t uuid)
returns timestamptz language plpgsql stable security definer set search_path = '' as $$
declare r public.tournaments; hit timestamptz;
begin
  select * into r from public.tournaments where id = t;
  if r.target is not null then
    select min(s.target_at) into hit
    from private.tournament_standings(t, least(r.ends_at, coalesce(r.ended_at, r.ends_at), now())) s;
    if hit is not null then return hit + interval '1 microsecond'; end if;
  end if;
  if r.ended_at is not null then return least(r.ended_at, r.ends_at); end if;
  if now() >= r.ends_at then return r.ends_at; end if;
  return null;
end $$;

-- Freezes a finished tournament's results, once.
create or replace function private.finalize_tournament(t uuid)
returns void language plpgsql volatile security definer set search_path = '' as $$
declare fin timestamptz; win uuid;
begin
  perform pg_advisory_xact_lock(hashtext('tournament:' || t::text));
  if exists (select 1 from public.tournaments where id = t and finalized_at is not null) then return; end if;
  fin := private.tournament_finish_at(t);
  if fin is null then return; end if;
  update public.tournament_members m
     set final_distinct = s.distinct_drinks, final_reached_at = s.reached_at, final_rank = s.rank
    from private.tournament_standings(t, fin) s
   where m.tournament_id = t and m.user_id = s.user_id;
  select s.user_id into win from private.tournament_standings(t, fin) s
   where s.rank = 1 and s.distinct_drinks > 0;
  update public.tournaments set finished_at = fin, winner_id = win, finalized_at = now() where id = t;
end $$;

create or replace function private.tournament_state(r public.tournaments)
returns text language sql stable set search_path = '' as $$
  select case when r.finalized_at is not null then 'finished'
              when now() < r.starts_at then 'upcoming'
              else 'live' end;
$$;

-- 6. Reads (volatile: they freeze a tournament that has just finished).
create or replace function public.tournament_board(t uuid)
returns jsonb language plpgsql volatile security definer set search_path = '' as $$
declare r public.tournaments; me uuid := auth.uid(); blocked uuid[] := private.my_block_set();
begin
  if me is null or not (t = any (private.my_tournament_ids())) then
    raise exception 'not_found' using errcode = 'P0001';
  end if;
  perform private.finalize_tournament(t);
  select * into r from public.tournaments where id = t;
  if r.host_id = any (blocked) then raise exception 'not_found' using errcode = 'P0001'; end if;
  return jsonb_build_object(
    'id', r.id, 'name', r.name, 'host_id', r.host_id,
    'starts_at', r.starts_at, 'ends_at', r.ends_at, 'target', r.target,
    'ended_at', r.ended_at, 'finished_at', r.finished_at,
    'state', private.tournament_state(r), 'daily_cap', private.tournament_daily_cap(),
    'winner_id', case when r.winner_id = any (blocked) then null else r.winner_id end,
    'winner_hidden', coalesce(r.winner_id = any (blocked), false),
    'my_status', case when r.host_id = me then 'host'
                      else (select m.status from public.tournament_members m
                            where m.tournament_id = t and m.user_id = me) end,
    'standings', coalesce((
      select jsonb_agg(jsonb_build_object('user_id', s.user_id, 'distinct', s.distinct_drinks,
               'today', s.today_counted, 'reached_at', s.reached_at, 'rank', s.rank) order by s.rank)
      from (
        select m.user_id, m.final_distinct::integer as distinct_drinks, 0 as today_counted,
               m.final_reached_at as reached_at, m.final_rank::integer as rank
        from public.tournament_members m
        where r.finalized_at is not null and m.tournament_id = t and m.status = 'accepted'
          and m.final_rank is not null
        union all
        select x.user_id, x.distinct_drinks, x.today_counted, x.reached_at, x.rank
        from private.tournament_standings(t, greatest(least(r.ends_at, now()), r.starts_at)) x
        where r.finalized_at is null
      ) s
      where not (s.user_id = any (blocked))), '[]'::jsonb),
    'invited', coalesce((
      select jsonb_agg(m.user_id order by m.invited_at) from public.tournament_members m
      where m.tournament_id = t and m.status = 'invited' and not (m.user_id = any (blocked))), '[]'::jsonb)
  );
end $$;

create or replace function public.my_tournaments()
returns table (id uuid, name text, host_id uuid, starts_at timestamptz, ends_at timestamptz,
               target integer, finished_at timestamptz, winner_id uuid, winner_distinct integer,
               state text, my_status text, members integer, my_rank integer, my_distinct integer)
language plpgsql volatile security definer set search_path = '' as $$
#variable_conflict use_column
declare me uuid := auth.uid(); tid uuid; blocked uuid[] := private.my_block_set();
begin
  if me is null then return; end if;
  foreach tid in array private.my_tournament_ids() loop
    perform private.finalize_tournament(tid);
  end loop;
  return query
  select t.id, t.name, t.host_id, t.starts_at, t.ends_at, t.target::integer, t.finished_at,
         case when t.winner_id = any (blocked) then null else t.winner_id end,
         (select w.final_distinct::integer from public.tournament_members w
          where w.tournament_id = t.id and w.user_id = t.winner_id),
         private.tournament_state(t),
         case when t.host_id = me then 'host' else m.status end,
         (select count(*)::integer from public.tournament_members x
          where x.tournament_id = t.id and x.status = 'accepted'),
         coalesce(m.final_rank::integer, live.rank),
         coalesce(m.final_distinct::integer, live.distinct_drinks)
  from public.tournaments t
  left join public.tournament_members m on m.tournament_id = t.id and m.user_id = me
  left join lateral (
    select s.rank, s.distinct_drinks
    from private.tournament_standings(t.id, greatest(least(t.ends_at, now()), t.starts_at)) s
    where s.user_id = me and t.finalized_at is null
  ) live on true
  where t.id = any (private.my_tournament_ids()) and not (t.host_id = any (blocked))
  order by t.starts_at desc
  limit 100;
end $$;

-- 7. Writes. Errors are P0001 with these messages, which the client maps:
--    not_found, not_allowed, finished, invalid_dates, invalid_goal,
--    too_many_tournaments, no_invitees, objectionable_content (detail 'tournament_name').
create or replace function private.add_invitees(t uuid, host uuid, people uuid[])
returns integer language plpgsql volatile security definer set search_path = '' as $$
declare room integer; added integer;
begin
  -- Seats are the people still in it or still asked: someone who declined
  -- or left frees theirs (and stays un-invitable, below).
  room := 50 - (select count(*) from public.tournament_members
                where tournament_id = t and status in ('invited', 'accepted'));
  insert into public.tournament_members (tournament_id, user_id)
  select t, p from (
    select distinct p from unnest(coalesce(people, '{}'::uuid[])) p
    where p <> host
      and exists (select 1 from public.follows f where f.follower_id = host and f.following_id = p)
      and not public.blocked_with(p)          -- auth.uid() is the host here
      and not exists (select 1 from public.tournament_members m
                      where m.tournament_id = t and m.user_id = p)   -- declined stays declined
    limit greatest(room, 0)
  ) ok;
  get diagnostics added = row_count;
  return added;
end $$;

create or replace function public.create_tournament(
  p_name text, p_starts_at timestamptz, p_ends_at timestamptz,
  p_target integer, p_tz text, p_invitees uuid[])
returns uuid language plpgsql volatile security definer set search_path = '' as $$
declare me uuid := auth.uid(); tid uuid;
begin
  if me is null then raise exception 'not signed in' using errcode = '28000'; end if;
  if p_starts_at < now() - interval '5 minutes' or p_starts_at > now() + interval '30 days'
     or p_ends_at - p_starts_at < interval '1 day' or p_ends_at - p_starts_at > interval '31 days' then
    raise exception 'invalid_dates' using errcode = 'P0001';
  end if;
  -- A goal the daily cap makes unreachable (First to 10 in 3 days) is refused.
  if p_target is not null and p_target > private.tournament_daily_cap()
       * ceil(extract(epoch from (p_ends_at - p_starts_at)) / 86400.0) then
    raise exception 'invalid_goal' using errcode = 'P0001';
  end if;
  if (select count(*) from public.tournaments x
      where x.host_id = me and x.finalized_at is null and x.ended_at is null and x.ends_at > now()) >= 5
     or (select count(*) from public.tournaments x
         where x.host_id = me and x.created_at > now() - interval '30 days') >= 10 then
    raise exception 'too_many_tournaments' using errcode = 'P0001';
  end if;
  insert into public.tournaments (host_id, name, starts_at, ends_at, target, tz)
  values (me, btrim(coalesce(p_name, '')), p_starts_at, p_ends_at, p_target,
          coalesce((select z.name from pg_timezone_names z where z.name = p_tz), 'UTC'))
  returning id into tid;
  insert into public.tournament_members (tournament_id, user_id, status, responded_at)
  values (tid, me, 'accepted', now());
  if private.add_invitees(tid, me, p_invitees) = 0 then
    raise exception 'no_invitees' using errcode = 'P0001';     -- rolls the whole call back
  end if;
  return tid;
end $$;

### 13.2 The `apple-music` Edge Function: contract

File: `supabase/functions/apple-music/index.ts` (Deno). Excluded from the app's `tsc` (`tsconfig.json` `"exclude": ["supabase/functions/**"]`) and lint (`eslint.config.js` ignores `supabase/functions/*`). Deployed from the Dashboard (Edge Functions → Deploy a new function → via editor, name `apple-music`, then turn **off** "Verify JWT with legacy secret"; see below).

**Secrets** (Dashboard → Edge Functions → Secrets): `MUSICKIT_KEY_P8` (the whole .p8 text, BEGIN/END lines included), `MUSICKIT_KEY_ID`, `APPLE_TEAM_ID`. Supabase provides `SUPABASE_URL` and the project's client key; this project uses the new `sb_publishable_` keys, whose variable is `SUPABASE_PUBLISHABLE_KEY` (legacy projects: `SUPABASE_ANON_KEY`), so the function reads `Deno.env.get('SUPABASE_PUBLISHABLE_KEY') ?? Deno.env.get('SUPABASE_ANON_KEY')` and answers 503 `not_configured` when neither is set. No key is ever in the app or the repo (`*.p8` is already gitignored). Its one import is `npm:@supabase/supabase-js@2` (a Deno specifier resolved at deploy; nothing is added to the app's `package.json`).

**"Verify JWT with legacy secret" goes off.** This project signs sessions with an ECC (P-256) key (Settings → JWT Keys), and that switch accepts only the legacy HS256 secret, so with it on every real user gets a 401. The handler checks the session itself (`auth.getUser()`, below), so the per-account budget never depends on the gateway. Found 7 Oct 2026 deploying `apple-revoke`.

**Request** (from the app: `supabase.functions.invoke('apple-music', { body })`, which sends the user's JWT):

```json
{ "action": "search", "term": "golden hour", "storefront": "us", "limit": 20 }
```

`term` 2 to 80 characters after trimming; `storefront` `^[a-z]{2}$`, default `"us"`; `limit` 1 to 25, default 20. Nothing else is accepted.

**Responses:**

| Status | Body | When |
|---|---|---|
| 200 | `{ "songs": Song[], "storefront": "us" }` | |
| 400 | `{ "error": "bad_request" }` | wrong method, body or field |
| 401 | `{ "error": "signed_out" }` | no valid user (the gateway usually answers first) |
| 429 | `{ "error": "rate_limited" }` | `charge_music_search()` returned false (120/hour/account) |
| 502 | `{ "error": "upstream" }` | Apple answered anything but 2xx/401/403 |
| 503 | `{ "error": "not_configured" }` | a secret is missing, or Apple refused the token (401/403) |

```ts
interface Song {
  id: string;            // Apple Music catalog song id, digits
  title: string;         // attributes.name
  artist: string;        // attributes.artistName
  album: string | null;  // attributes.albumName
  artworkUrl: string | null; // attributes.artwork.url with {w} and {h} set to 300
  previewUrl: string;    // attributes.previews[0].url (https://audio-ssl.itunes.apple.com/...)
  appleMusicUrl: string; // attributes.url (https://music.apple.com/...)
  durationMs: number | null;
  storefront: string;
}
```

**Behaviour:**

1. Signs a MusicKit developer token: header `{ "alg": "ES256", "kid": MUSICKIT_KEY_ID, "typ": "JWT" }`, claims `{ "iss": APPLE_TEAM_ID, "iat": now, "exp": now + 12 h }`, signed with WebCrypto (`importKey('pkcs8', …, { name: 'ECDSA', namedCurve: 'P-256' })`, `sign({ name: 'ECDSA', hash: 'SHA-256' })`, whose 64-byte r‖s output is exactly what JWS ES256 wants), base64url throughout. Cached in module scope until 5 minutes before expiry; dropped on a 401/403 from Apple.
2. Checks the user (`createClient(SUPABASE_URL, <client key>, { global: { headers: { Authorization } } }).auth.getUser()`), then charges the budget with the same client (`rpc('charge_music_search')`), so the count is per account.
3. `GET https://api.music.apple.com/v1/catalog/{storefront}/search?types=songs&limit={limit}&term={encodeURIComponent(term)}` with `Authorization: Bearer {developer token}`. If Apple answers 400 or 404 for a storefront other than `us` (a region with no storefront of its own), it retries once with `us` and reports `storefront: "us"`.
4. Maps `results.songs.data[]` to `Song`, **dropping** any song with `contentRating === 'explicit'`, with no preview, or whose preview, artwork or link host fails the same patterns as `post_photos_music_shape`, so anything it returns can be stored.
5. Caches each answer in memory for 10 minutes by `storefront|term(lowercased)|limit`, at most 200 entries.
6. Logs nothing about the user or the term.

## 18. The origin story contract

### 18.1 What the writers produce

- Directory `scripts/origindata/`, one file per batch: `batch-01.json` … `batch-21.json`.
- **Batch NN covers the drinks whose `dexNumber` is (NN − 1) × 100 + 1 to NN × 100** (batch-01 is #1 to #100, batch-21 is #2001 to #2089). Dex numbers are 1 to 2,089 with no gaps today.
- Each file is one JSON object, keys in dexNumber order, UTF-8, 2-space indent, trailing newline:

```json
{
  "negroni": "Florence, 1919, by most accounts: Count Camillo Negroni asked the bartender at Caffè Casoni …",
  "americano": "…"
}
```

- Keys are catalogue ids exactly as in `src/data/drinks.json`; values are the story. A writer omits a drink only when no defensible story can be written (the app then falls back to its fun fact). One writer per file; nobody else edits it.
- Writers read `src/data/drinks.json` (read-only: never write it, or any other file) for their range's `id`, `name`, `category`, `subcategory`, `origin`, `description` and `funFact`, and research from there. They may check their own file with `node -e 'JSON.parse(require("fs").readFileSync(process.argv[1],"utf8"))' scripts/origindata/batch-NN.json`.
- Optional sidecar `batch-NN.flags.json`, `{ "<id>": "<note for Jan>" }`, for anything a writer found wrong in the catalogue (an origin field that sources contradict, a name that is wrong). The merge never reads it.

### 18.2 The story, rules every writer follows

1. **One paragraph, plain text**: 300 to 800 characters (about 50 to 130 words; aim for 75 to 110). No line breaks, markdown, HTML, emoji or URLs. English, sentence case; acronyms (AOC, DOCG, USA) are fine.
2. **What it tells**: where and when the drink began, who is credited, how it got its name, and how it travelled. For a spirit brand, the brand's or distillery's beginnings; for a spirit style, the style's. It may not contradict the card's `origin` field; if research says the field is wrong, write the story to what the sources support and flag it in the sidecar.
3. **The first year between 1500 and 2029 in the story is the origin year** (the drink page's dateline takes exactly that: "Florence, Italy · 1919"; a decade such as "the 1920s" is read as "1920s"; a year before 1500 is not read, so "since the 1300s" can precede it harmlessly). If there is no origin year, use no four-digit year before any later one ("revived in 2008" is fine only when no origin year exists and the revival is not mistaken for it, so prefer "in the late 2000s").
4. **Researched, and honest about uncertainty**: legends are told as legends ("the story goes", "by most accounts"); disputed origins say who claims what; no invented names, bars, dates or quotes. If unsure, leave it out.
5. **Fold in the fun fact if it is true**: the card stops showing `funFact` once a story exists.
6. **Responsible**: never celebrate quantity, drunkenness or speed; no health claims; no "the best"; nothing that encourages drinking more (App Review 1.4.3). No defamatory claims about living people. Brands may be named.
7. **Not the description again**: the card already shows the description and the tasting notes.

### 18.3 The merge (package O, after the writers)

**Where it is wired: `scripts/lib/dex-merge.mjs`**, the shared machinery every catalogue writer already goes through, so a later run of `merge-cocktails.mjs`, `merge-world-spirits.mjs` or `merge-spirit-brands.mjs` (each of which rebuilds whole rows from its source files and would otherwise drop a field it does not project) keeps the stories.

```js
/**
 * Reads scripts/origindata/batch-NN.json (only files matching /^batch-\d{2}\.json$/, in
 * name order) and returns the rows with `originStory` set as the LAST key of every row
 * that has one, and removed from every row that does not (never an empty string), so
 * two runs, from any script, write the same bytes.
 * strict: problems in the story files are errors (merge-origin-stories); otherwise warnings,
 * and only valid stories are attached (a cocktail merge is a bystander to the stories).
 */
export function attachOriginStories(rows, { strict = false } = {}) // -> { out, errors, warnings, report }
```

- `merge({ drinks, incoming })` calls `attachOriginStories(out)` on its result before returning it, and keeps its return shape (`{ out, added, fresh, refreshed }`, with `out` now carrying the stories). The merge scripts call `reportAndGate` *before* `merge()`, so `merge()` prints the story warnings itself (`console.warn`, at most 20 and a count) and never exits on them; a cocktail merge is a bystander to the stories. No directory, no change, no output.
- The directory is resolved from the module, `new URL('../origindata/', import.meta.url)`, never from the working directory.
- Checks, per entry: the file parses to an object of string → string; the id exists in the rows (error); the id's dexNumber is inside the file's batch range (warning: misfiled, still attached); an id in two files (error); length 300 to 800 after trimming (error); no `\n`, `\r`, `<`, `](`, `http`, `www.` or emoji (`/\p{Extended_Pictographic}/u`) (error); the story has a year between 1500 and 2029 (warning when it has none). The value attached is the trimmed string, so a re-run is byte-identical.
- An id that `remove-drinks.mjs` or `prune-nonalcoholic.mjs` later takes out of the catalogue becomes an "unknown id" error for the strict runner (delete its entry from the batch file) and a warning for the merge scripts.
- Report: stories attached of 2,089, per batch; ids missing a story (count, and the first 20); bytes added to drinks.json. **Budget: at most +1.7 MB** (drinks.json is 3.2 MB; 2,089 stories at ≈550 characters is ≈1.15 MB); over it is a warning naming the longest stories.

**New runner `scripts/merge-origin-stories.mjs`**: reads `src/data/drinks.json`, runs `attachOriginStories(drinks, { strict: true })`, prints the report, stops on any error with nothing written, `--dry` writes nothing, otherwise writes `JSON.stringify(out, null, 1) + '\n'` (the merge scripts' format) and exits 0. Idempotent.

## 19. Build plan

### 19.1 Rules

1. **One owner per file per stage.** Only the owning package edits a file; a package that needs something in another's file asks that owner. Every file this spec touches is in exactly one row of §19.2, §19.3 or §19.4 for its stage. Z (stage 3) edits files F and S owned in stage 1, after both have merged and nobody else is editing them.
2. **Stage 1** (F, N, S) runs in parallel. **No stage-1 package imports another stage-1 package's new code** (checked for every file: N needs no new token or glyph, since `tabIcon('bottle')` draws the existing outline and picks up F's solid bottle when both have merged; F's song UI types itself structurally; S has no UI).
3. **Stage 2** (H, X, R, W, T, C, D) runs in parallel on top of merged stage 1, importing stage-1 code freely. **No stage-2 package imports another stage-2 package's new code**; links to tournament routes go through `src/lib/tournaments.ts`'s `as Href` helpers.
4. **Stage 3** (Z, O) runs after every stage-2 package has merged. Z is the rarity close-out (§19.4). O is the origin merge (§18.3) and needs all 21 writer files (§18.1): if any is missing it stops and reports, and writes nothing. Z's and O's files are disjoint, so they run in parallel.
5. **Writers** (the Origin stories phase) are not a build package: they create only `scripts/origindata/batch-NN.json` (+ optional `.flags.json`), read `src/data/drinks.json` and nothing else of the tree, and can run at any time before O.
6. **Worktrees**: one per package under `~/Projects/drinkdex-worktrees/v31-<key>` (`v31-f`, `v31-n`, …), branched from `v3-changes` and merged back into it; never share one.
